# 跨项目页面开发标准

以下为用户确认的个人默认标准。当前只适用于 PC 网站中的表单、管理后台、看板等对应场景；手机端开发和验收暂不纳入，用户明确要求后再安排。明确的新需求优先；品牌、业务数据和权限不从来源项目继承。

仅应用本次任务涉及的条款：没有表格不新增表格，没有日期选择不引入日期组件，没有网络请求不增加查询状态。规则用于约束已有或已授权功能，不用于扩展需求；确实涉及但未完成的验证如实标记未验证。

## 日期与时间

- 涉及日期、日期范围或时刻选择时，读取 [date-time-components.md](date-time-components.md)，使用本 Skill 自带的对应组件。
- 不因为另一个组件库更方便就替换已确认的选择器。框架适配可以改变接入代码，保留原交互和外观；明确记录不兼容点和必要扩展。
- 对已有网站只在本次涉及的选择器范围内应用，不顺手替换全站。若项目规则明确要求另一实现，先说明冲突；尊重当次用户指令。

## 页面空间

- 看板和管理页面随可用内容区展开，避免窄容器居中产生过大的左右空白。侧栏展开、收起及宽屏下都要检查。
- 首屏优先核心数据、筛选、表格；减少重复标题、装饰卡片和低频整行说明。不以缩小字号、挤压操作区域来增加密度。
- 文章、阅读内容和简单表单按可读性设置宽度，不强行铺满。没有已确认的项目数值时，按实际视口判断，不把某个边距数值当成用户固定要求。
- 验收检查常用桌面宽度下内容宽度、表格起点、可见数据行及页面横向溢出。设备范围按任务决定，不因引入组件自动扩大开发范围。

## 数据请求与结果状态

| 场景 | 必须表现 |
| --- | --- |
| 首次读取且没有结果 | 显示明确的加载提示或骨架；不能先显示一排假 0 |
| 已有结果再次查询 | 保留上次完整结果，结果区显示“正在查询，当前显示上次结果” |
| 条件变化但查询尚未完成 | 标明当前展示结果对应的原条件；不能用新日期、新用户标题误标旧结果 |
| 查询成功 | 指标、列表、合计、结果条件、更新时间按同一批次一起替换 |
| 成功但结果为空 | 替换旧结果，显示“该条件下暂无结果” |
| 查询失败 | 保留最后完整结果，说明失败及旧结果范围，提供重试；无旧结果时显示错误状态 |
| 快速连续查询 | 仅最新请求可更新当前页面；关闭弹窗、切换对象后旧响应不得回填 |

- 原结果只供参考；切换用户/业务期间，禁用依赖旧结果的编辑、删除、支付等操作，避免身份错配。旧对象内容不适合保留时，在目标区域以加载状态代替，并明确原因。
- 普通自动读取不清空筛选、分页和滚动位置，不打断输入；数据不变时避免整表重绘。
- “查询已有结果”与“重新采集上游”有不同成本和权限，不把普通筛选自动升级为高成本采集。

## 表格、筛选和数值

- 同列的表头、排序控件、数据和合计保持一致对齐；数值按项目规范统一，不强制所有内容居中。
- 全部筛选结果排序后再分页，注明合计是当前页还是全部筛选结果；服务器分页时由服务器完成全量排序。
- 长表按需要固定表头；宽表在自己的区域内横向滚动，主要身份列按场景冻结，交叉处不能遮挡。
- 金额和核心指标完整可读，提供单位。真实 0、缺失“—”、查询失败、尚未更新分别表达。
- 筛选提供明确的重置方式；返回、重开、自动刷新是否保留条件应一致。日期和条件可适当保存到网址，不把凭据或敏感身份写入网址。

## 保存、弹窗和反馈

- 保存中明确反馈并避免重复提交；实际保存成功后才显示成功。失败保留用户输入，便于修正和重试。
- 弹窗有明确标题和关闭入口；超高内容在内部滚动，标题与主要动作可达；关闭恢复焦点及原页面位置。
- 二层详情返回保留上层条件；打开、关闭、重开、切对象、慢响应都要验收。
- 错误用中文说明发生了什么、旧结果是否保留、下一步怎么做。不得只用颜色区分状态。

## 验收方法

开发涉及哪种行为，就实际验证对应状态：首次加载、再次查询、失败保留、成功为空、快速换条件、保存失败、重复打开及滚动。静态截图不能证明交互正确。共享组件调整需检查调用页面；不要为本次任务修改无关页面。
