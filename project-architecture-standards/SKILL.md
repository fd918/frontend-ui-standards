# 项目架构经验规范

## 适用范围

仅在本次任务真正涉及架构选择或边界变化时启用。先读取项目已有规则、说明、结构、关键依赖和相关代码，结合 Git 状态确认现状；不能把历史文档中的设想当成已运行架构。

普通页面、文案、样式或单函数修复，沿用既有架构，不开展全项目设计。项目存在数据库、队列或多个服务，不表示每次修改都要重新评估它们。架构调整只能服务于已授权目标，不自动授权数据迁移、服务切换或公开发布。

| 本次任务 | 本次应考虑 | 不自动执行 |
| --- | --- | --- |
| 简单静态网站 | 页面及资产组织、需要的托管方式 | 后端、登录、数据库或微服务 |
| 新增展示页面，已有数据可用 | 现有共享数据入口、页面边界与权限 | 重复采集、另建主数据源 |
| 新增来源或多个页面共用指标 | 采集、校验、保存、计算、查询的数据流 | 中央数据平台、所有数据迁移 |
| 新增登录、多账号或跨项目共享 | 身份、数据归属和授权边界 | 无需求的完整组织权限平台 |
| 长任务影响交互或需要重启恢复 | 运行单元、队列、状态及失败边界 | 默认独立服务、外部队列产品 |
| 服务或数据结构确需调整 | 依赖关系、兼容路径、分步验证和回退 | 顺手重构无关模块 |

## 应用的架构经验

1. **规模决定复杂度。** 选择满足当前需求的最小结构；简单脚本、静态站点和持续运行的业务系统分别处理。没有现实需求时不预建多服务、插件平台或通用配置层。
2. **职责边界明确。** 页面负责展示交互；接口负责请求边界与身份检查；业务模块负责规则计算；存储负责持久化；采集负责来源接入。小项目可用少量函数实现，不强制每层单建目录或服务。
3. **权威来源唯一。** 同一业务事实和同一计算口径明确由谁维护。数据库、文件镜像、缓存和派生页面并存时，写清主从方向，避免相互覆盖；不同来源与业务含义不强行合并。
4. **先明确数据流。** 按实际需要描述“来源 → 完整性校验 → 保存 → 共享计算 → 查询 → 页面”。不需要的环节可以省略；新看板优先接入现有链路，不另建重复采集和计算。
5. **查询、保存和采集分工。** 普通读取不隐式触发昂贵刷新，耗时网络任务不占住交互短写入。原始数据、派生状态与人工编辑各有所有权，后台任务不能用旧对象覆盖新编辑。
6. **故障范围可控。** 无关数据源或业务的失败不拖垮全部结果；确实互相依赖的结果，完整后再发布。对外说明旧数据、缺失与失败，避免半批次和假成功。
7. **共享有边界。** 组件、接入封装和业务计算按职责复用；账号、项目和受限数据保持归属隔离。跨项目通过明确的接口或数据契约提供必要字段，不靠共享正式凭据或全库权限实现复用。
8. **运行单元按负载拆分。** 小项目可单进程按模块组织。实际出现网页阻塞、独立调度、资源隔离或恢复要求时，再评估独立执行单元；同时确定状态归属、重复执行保护和运维成本。
9. **环境差异配置化。** 开发、测试和正式尽量沿用同一套程序，以配置区分。已有正式专用版本时，先保护可信基线与账号能力，再计划收敛，不直接覆盖。不同项目共用机器不等于共用业务权限和数据。
10. **升级兼容已有使用者。** 接口、组件、数据结构和持久化算法分别记录实际需要的版本。修改契约前查清调用方，考虑旧数据和在途任务；明确部署次序。代码回退不能自动恢复数据库或覆盖新业务数据。
11. **扩展入口可找到。** 复用项目已有的菜单、权限、存储、任务或发布登记入口；只登记新能力实际涉及的内容。多个清单表达同一事实时尽量由单一登记派生，避免各处复制和遗漏。
12. **保留决策原因。** 记录真实采用的分工、数据流、取舍、适用条件和已知限制。替换旧决策时更新冲突内容，保留必要背景，不持续叠加两套现行方案。

## 输出与验证

- 实现前按复杂度简述所选结构、受影响模块、复用位置及验证方式。简单任务一段话即可；不强制每次绘图或创建架构文档。
- 持续开发的项目优先在已有项目背景或架构文档维护实际模块职责、数据流、共享边界和关键决策；没有合适文档且确有后续维护需要时才创建最小必要文档。
- 根据改动验证跨模块契约、同批数据一致性、权限隔离、失败保留或升级兼容等实际受影响路径。选择需要改变事实的证据，不以文件中存在函数名或单纯 HTTP 200 代替功能验证。
- 区分已验证、不适用、未验证。不适用项直接跳过；需要但暂时无法验证的事项说明影响，不能借此声称架构调整完成。
- 架构规则负责边界和取舍。前端控件、布局及交互按可用的前端规范执行；后端接口、存储和发布细节按可用的后端规范执行。未安装相应 Skill 时说明情况，继续使用项目现有规则，不自行安装或扩大任务。

本 Skill 总结了既有看板、账号工具、知识库和通知助手的架构经验，不携带这些项目的部署路径、账号、凭据或数据。开发中的明确用户要求优先于本规范的默认建议。
