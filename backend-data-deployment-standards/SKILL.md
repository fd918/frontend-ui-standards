# 后端、数据复用与部署规范

## 先判断适用性，再执行规则

**本 Skill 是按需规则集，不是必须全部实施的功能清单。是否适用同时取决于项目现状和本次任务。**

- 先读取与任务相关的项目规则、说明、依赖、关键代码和 Git 状态，确认真实环境及已有实现。
- 用一段简短说明列出本次涉及的能力和验证方法。简单任务不要求额外制作适用性报告或建立文档。
- 没有涉及的模块直接跳过，不能为了遵守规则而新增数据库、服务端、登录、缓存、队列或监控系统。
- 项目有数据库但本次只改静态文案，不因此执行数据库迁移或恢复演练；项目有后台任务，也不代表每次改动都需等待整个任务周期。
- 确实涉及但无法完成的检查应标明未验证及影响，不能写成“不适用”来绕过；需要安全前置检查的实际生产变更仍遵守项目要求。
- 发现未来扩展可能有价值时，可作为建议提出，不纳入本次实现，除非任务确实需要或用户明确要求。

| 本次实际场景 | 适用规则 | 不应自动增加的内容 |
| --- | --- | --- |
| 只改静态展示内容 | 普通前端规则；发布时再执行静态发布检查 | 后端、登录、数据库、缓存和队列 |
| 读取外部或已有接口 | 数据来源、接入复用、权限边界和错误处理 | 独立数据库、定时采集器或缓存服务 |
| 多个页面使用同一指标 | 权威来源、共享计算；实际有缓存时再执行缓存规则 | 每页重复采集或维护第二套计算 |
| 保存文件、浏览器本地数据或第三方表格 | 数据归属、保存回读、失败保护；按价值决定备份 | SQL 数据库、表结构迁移 |
| 读写数据库 | 主存储、数据关系及查询规则；改结构才启用迁移规则 | 无关表迁移、全量重建、默认双写 |
| 长任务、定时采集或外部通知 | 任务状态、超时、防重复；需跨重启时再持久化恢复 | 所有任务上消息队列产品或拆成微服务 |
| 有登录、多账号或受限数据 | 服务端身份校验、数据归属与权限 | 无业务需求的完整角色管理后台 |
| 本地运行或静态托管发布 | 实际运行所需的启动、构建、资源和地址检查 | 正式数据库备份、服务器停服与重启流程 |
| 更新正式服务或正式数据 | 明确版本、保护配置与数据、受影响流程验收、回退 | 重启无关服务、复制其他项目的环境参数 |

## 数据复用（涉及数据接入、共享或更新时）

1. **明确来源和责任。** 记录需要复用的数据从哪里来、由谁更新、保存在哪里、哪些功能使用；简单功能可在已有说明中记录，不强建数据管理平台。
2. **复用接入能力。** 同一来源的认证、分页、限速和错误处理集中维护；已有采集结果满足时优先读取，不重复请求上游。实时性或隔离要求不同的来源不能强行合并。涉及凭据时使用项目已有安全配置或安全存储，不将真实密钥、Cookie 或密码放进源码、日志或发布包。
3. **共享计算结果。** 同一业务口径的指标只有一个权威计算入口。派生页面读取同一批计算结果，不只共享原始数据却各自套用不同规则。
4. **共享仍受授权限制。** 跨项目优先通过明确接口或约定的数据契约读取必要字段，限制账号和数据范围。不能因为可复用就给新项目全量正式库权限；也不为一次复用提前建设中央数据平台。
5. **保护人工内容。** 原始采集、派生结果、人工备注和调整各有所有权，采集只提交其负责字段，不用采集开始时的旧对象覆盖后续人工保存。
6. **完整后再发布。** 涉及分页、附件或多来源时先验证完整性，再替换旧批次；失败保留最后完整结果并标明范围。成功的空结果与失败分开，不把缺失当 0。区分数据日期、采集时间和历史修订时间。
7. **实际存在缓存时才管理缓存。** 缓存身份覆盖真正影响结果的来源、账号、业务、日期及规则版本。保存后统一失效相关列表、详情和汇总，并阻止旧在途结果重新落地。派生结果持久化且算法变化时，才增加对应版本与兼容重建。

## 后端开发（涉及服务端逻辑或后台执行时）

8. **按职责组织。** 来源接入、业务计算、存储和接口按已有架构分工，不继续无边界堆入大文件；小项目可使用简单函数或模块，不强制拆服务、增加抽象层。
9. **读取和采集分开。** 普通查看、筛选和翻页读取已有数据；重新采集由明确入口或已有后台计划触发。仅查询已有结果的操作不静默升级成昂贵采集。
10. **长短操作分开。** 确有长任务时采用适合规模的异步执行或队列，避免阻塞备注保存等交互。进程内队列已足够时，不引入外部队列产品。
11. **任务按副作用设计。** 长任务有状态、主动执行期限和有限重试；需要重启续跑时保存进度。外部写入、通知或重复调度使用稳定去重身份；发送结果不确定时先核对，不盲目重发。仅让用户等待超时不等于底层任务已取消。
12. **接口明确校验。** 参数在服务端校验；涉及登录或受限数据时，每次读写校验身份、对象归属和动作权限。接口错误、数据是否可读和本轮刷新状态分开表达；不能只隐藏按钮，也不能把可用历史数据与刷新失败一起拒绝。

## 存储与数据库（仅执行当前存储方式对应的部分）

13. **明确主存储。** 存在持久化时确定权威来源；数据库、文件镜像和缓存并存时不能互相任意覆盖。没有持久化需求就不增加存储；使用文件或第三方存储不强制数据库化。写入失败不能假报成功或静默改写另一套主存储。
14. **结构按实际查询设计。** 确有数据库时，账号、订单和流水等关系明确的数据采用适合查询和约束的结构；灵活配置可用文档。不要所有内容塞进一个巨型文档，也不为小配置过度拆表。
15. **保护关联与并发。** 涉及关联和多项写入时，使用稳定编号、适当唯一约束与事务；账号归属参与读写条件。按需求处理并发冲突，金额使用精确数值或最小货币单位，避免浮点误差。不要求无关联的单次读取引入事务。
16. **改结构才做迁移。** 表结构、约束或历史数据转换使用版本化、尽量可重复执行且兼容的迁移。正式执行前说明历史影响、备份、恢复或回滚方式；不以重建表代替安全兼容变更。程序回滚不等于可安全撤销数据库结构或新增数据。
17. **备份与性能按影响验证。** 有重要持久化数据时建立合适的备份并验证恢复，正式库使用独立环境演练，不为每次无关小改重复演练。查询变慢或规模需要时检查索引、分页、字段投影、批量读取及连接池压力，先测量，不盲目增大资源。

## 部署与运行（仅在启动、安装或发布任务中启用）

18. **隔离实际环境。** 有开发、测试、正式环境时隔离配置、账号和数据；本地预览不默认运行正式通知和采集。同机多项目保留各自的应用配置、数据权限和进程边界，不照搬端口、任务名或数据库账号。
19. **从明确版本发布。** 正式发布记录源版本和文件清单，验证同一份构建成品，环境差异优先配置化。已有项目存在特殊正式版本时尊重其基线与增量规则，不直接整包覆盖。静态发布只检查实际需要的构建和静态资产。
20. **只更新授权范围。** 普通程序发布保护密钥、数据库、业务设置、上传文件和运行数据；确需变更时单独说明影响及恢复方案。涉及服务切换时协调真实在途任务，在实际临停前复查，不停止无关服务。
21. **验证实际生效。** 仅文件更新、PID 变化或 HTTP 200 不代表功能完成。对受影响入口核对运行版本、真实网址、权限和核心操作；修改自动采集逻辑时观察一次相关真实执行。纯静态页面不执行数据库、会话或采集检查。
22. **回退和监测匹配场景。** 有正式运行服务时保留可信回退版本，按需要监测数据新鲜度和任务状态。静态网站可使用托管平台已有版本回退；仅本地工具给出实际停止与恢复方法，不强建生产监控。代码回退不得用旧数据覆盖发布后新业务记录。

## 使用边界与交付

只要求本次实际涉及且必要的验证。交付简述已做事项、验证结果和仍有影响的未验证项；不把全部 22 条变成每次必须完成的检查表。明确授权仍按用户和项目规则处理：读取本 Skill 本身不授权修改正式数据库、停服、发送通知或公开发布。

本规范提炼自已有业务看板的数据共享与迁移、账号工具的数据隔离、知识库的内容发布及通知助手的任务恢复经验。各项目具体机器、路径、凭据、技术栈和操作命令不随经验迁移。涉及可能变化的平台行为时按当前项目核实官方资料。
